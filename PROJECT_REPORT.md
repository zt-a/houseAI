## Цель работы

Разработать модель машинного обучения для прогнозирования стоимости квартир в городе Бишкек на основе данных с сайта housekg.kg.

## Подготовка датасета

### Источник данных
Данные были получены из SQLite базы данных `housekg.db`, содержащей таблицу `properties` с объявлениями о недвижимости с сайта housekg.kg.

### Первичная обработка
1. **Фильтрация** - отобраны только квартиры (`property_type = 'Apartment'`) в городе Бишкек (`city = 'Бишкек'`)
2. **Очистка** - удалены объявления без цены или площади, применены диапазонные фильтры
3. **Фильтрация выбросов** - ограничение по площади (15-250 м²), цене (1-40 млн сом), цене за м² (10-200 тыс сом/м²)

### Feature Engineering
В процессе работы были созданы следующие признаки:

**Базовые числовые:**
- `total_area`, `rooms_num`, `floor_num`, `floors_total_num` - площадь, комнаты, этажность
- `year_built_num`, `age` - год постройки и возраст здания
- `ceiling_height_num`, `living_area_num`, `kitchen_area_num` - высота потолков, жилые и кухонные площади
- `dist_bishkek_center_km` - расстояние до центра Бишкека (рассчитано по формуле Haversine)

**Производные признаки:**
- `age^2`, `area^2`, `floor_ratio^2` - полиномиальные признаки для учета нелинейности
- `area_per_room`, `living_ratio`, `kitchen_ratio` - соотношения площадей
- `floor_ratio` - соотношение этажа к этажности
- `area_x_rooms`, `area_x_dist` - взаимодействия признаков
- `is_first_floor`, `is_last_floor`, `is_studio` - бинарные признаки

**Геопространственные:**
- **KMeans кластеризация** (15 кластеров) по координатам lat/lng для выявления ценовых зон

**Категориальные признаки:**
- Обработаны через парсинг `address` для извлечения микрорайонов (так как исходный `district` был пустым)
- `condition_cat`, `heating_cat`, `seller_type_cat`, `documents_cat` и другие
- **Target Encoding** с KFold кросс-валидацией для `district_clean` во избежание утечки данных

**Парсинг JSON:**
- Извлечены признаки из полей `features_json` (балкон, лифт, домофон, охрана и др.)
- Отобраны только наиболее частые признаки (встречающиеся >3% объявлений)

## Алгоритмы машинного обучения

### Модели
Использовался **ансамбль** из двух градиентных бустингов:

1. **CatBoostRegressor** - особенность в автоматической обработке категориальных признаков, устойчив к переобучению
2. **LightGBMRegressor** - быстрый и эффективный градиентный бустинг

### Трансформация целевой переменной
- Обучение производилось на логарифмированной цене: `log1p(price_som)`
- После предсказания применялось обратное преобразование: `expm1(pred_log)`
- Это позволило снизить влияние асимметрии распределения цен

### Валидация
- **10-fold KFold кросс-валидация** для объективной оценки модели
- **Optuna** для подбора оптимальных весов бленда
- Оптимальное соотношение: **CatBoost 70.7% / LightGBM 29.3%**

## Возникшие проблемы и их решение

| Проблема | Решение |
|---|---|
| Поле `district` пустое у всех записей | Разработан парсер для извлечения микрорайонов из поля `address` |
| Большой размер `housekg.db` (>100MB) | Исключен из git-репозитория через `.gitignore` и `git filter-branch` |
| Асимметричное распределение цен | Применено логарифмическое преобразование целевой переменной |
| Категориальные признаки с высокой кардинальностью | Использован Target Encoding с KFold для избежания утечки данных |
| Различия в алгоритмах моделей | Применен блендинг (взвешенное усреднение) CatBoost и LightGBM |
| Проблемы с совместимостью FastAPI/Starlette в Python 3.14 | Обновлены библиотеки, адаптирован код под новый API |
| Модель требует все признаки из обучающего набора | Реализовано автодополнение недостающих `feat_*` признаков нулями |
